# Sitemap Generator Documentation

## Overview

The HubSpot Sitemap Generator is a Python-based tool that creates XML sitemaps for multiple domains and regions. It uses data from the project spreadsheet, automates the generation of sitemap files, and creates sitemap index files that reference both HubSpot-generated and custom sitemaps.

The system features the following configuration architecture: a master **Alternate Links Setup** page defines all language/region combinations, the **SEO Planner** page uses both hard-coded URLs and formulas to manage content, and the Python script converts this into sitemap files.

---

## System Architecture

### How the Parts Connect

The system consists of four main components that work together in a smart, interconnected way:

#### 1. **Master Configuration: Alternate Links Setup Sheet**
- This is the **source of truth** for all language/region combinations
- Defines every language and region your websites support
- Structure includes:
  - **Column B:** Language (e.g., "English", "Spanish; Castilian")
  - **Column C:** Region (e.g., "Australia", "New Zealand", "United States of America")
  - **Column D:** Auto-generated locale codes
  - **Column E:** URLs for the homepage for each language/region combination

- **This is where you add new regions/languages** — when you add a row here, it automatically becomes available as a new column in the SEO Planner through formulas

#### 2. **Content Management: SEO Planner Sheet**
- The primary working sheet where URLs are managed
- Has a sophisticated hybrid structure:
  - **Row 1:** Domain identifiers
  - **Row 2:** Column headings — formulas that pull language/region descriptions from Alternate Links Setup (e.g., "English | Australia")
  - **Row 3:** Internal language/region codes that formulas use for lookups
  - **Columns B-D (Rows 4+):** Hard-coded URLs for the primary domains
  - **Columns E+ (Rows 4+):** Formula-based URLs that automatically pull from columns B-D based on the language/region codes

- The formula-based columns use `INDIRECT()`, `ADDRESS()`, `MATCH()`, and `VLOOKUP()` to dynamically reference earlier columns

#### 3. **CSV Export: data.csv**
- Generated by exporting the SEO Planner sheet as a CSV
- Acts as the input file for the Python script
- The formulas in the SEO Planner resolve to their calculated values when exported
- File is placed in the same directory as the Python script before running

#### 4. **Python Script: sitemap-generator.py**
- Reads the CSV data (now containing resolved URL values)
- Identifies all domains/regions and language variations
- Generates two types of XML files for each domain:
  - **Custom Sitemap:** Contains all URLs from the spreadsheet with language alternates
  - **Sitemap Index:** References both the HubSpot sitemap and the custom sitemap
- Outputs all files to a `sitemaps/` folder

### Data Flow Diagram

```
Alternate Links Setup (Master Config)
    ↓
    └──→ Formulas in SEO Planner
         (Columns B-D: Hard-coded URLs)
         (Columns E+: Formula-based URLs pulling from B-D)
         ↓
    Export to CSV
    (Formulas resolve to values)
         ↓
    data.csv (input)
         ↓
    sitemap-generator.py
         ↓
    ┌────┴──────┐
    ↓           ↓
Sitemaps/   Index Files
(custom)    (references HubSpot + custom)
```

## File Structure Details

### Understanding the SEO Planner Sheet

The SEO Planner has a hybrid design:

```
Column:     A           B               C               D               E                   F
Row 1:      [Blank]     example-com     example-co-nz   example-es      [Empty]             [Empty]
Row 2:      Page        En | Australia  En | NZ         ES | No region  En | Puerto Rico    En | Virgin Is
Row 3:      [Blank]     [lang code]     [lang code]     [lang code]     [lang code]         [lang code]
Row 4:      Homepage    [Hard-coded]    [Hard-coded]    [Hard-coded]    =FORMULA            =FORMULA
Row 5:      About       [Hard-coded]    [Hard-coded]    [Hard-coded]    =FORMULA            =FORMULA
```

**Key points:**

- **Columns B-D (Hard-coded zone):** These columns contain manually entered URLs for the primary domains. When you need to add or update a page for these domains, you enter the URL directly.

- **Columns E onwards (Formula zone):** These columns contain formulas that:
  - Look at the column heading (Row 2) to determine which language/region is needed
  - Look at Row 3 to get the language/region code
  - Search the Alternate Links Setup sheet to find the matching language/region row
  - Use `INDIRECT()` and `ADDRESS()` to retrieve the URL from the appropriate hard-coded column
  - Example formula: `=IFERROR(INDIRECT(ADDRESS(4,MATCH(VLOOKUP(E3,'Alternate Links Setup'!$D:$E,2,FALSE),$4:$4,0),1)&":"&REGEXEXTRACT(ADDRESS(4,MATCH(VLOOKUP(E3,'Alternate Links Setup'!$D:$E,2,FALSE),$4:$4,0),1),"[A-Z]+")),"")`

- **Benefits of this design:**
  - The first domains have direct, easy-to-edit URLs
  - Additional domains/regions automatically populate from the hard-coded columns
  - Reduce duplication and formula complexity
  - New language/regions added to Alternate Links Setup automatically become available

### How Data Is Organized in the CSV

When you export the SEO Planner sheet to CSV, the formulas resolve to their actual values:

```
Column:  A          B               C               D               E                   F
Row 1:   [Blank]    example-com     example-co-nz   example-es      [Empty]             [Empty]
Row 2:   Page       En | Australia  En | NZ         Es | No region  En | Puerto Rico    En | Virgin Is
Row 3:   [Blank]    [code]          [code]          [code]          [code]              [code]
Row 4:   Homepage   https://...     https://...     https://...     https://...         https://... (all resolved from formulas)
Row 5:   About      https://...     https://...     https://...     https://...         https://... (all resolved from formulas)
```

**Key points:**
- All formula-based columns now contain actual URL values (not formulas)
- The structure is flat and ready for the Python script to read
- Each column represents one domain/region combination
- Empty cells are ignored by the Python script

### Generated Output Files

For each domain in the CSV, two XML files are created in the `sitemaps/` folder:

1. **`[domain]-sitemap.xml`** - Custom Sitemap
   - Contains all URLs from the spreadsheet
   - Includes `<xhtml:link>` tags showing alternate language versions
   - Only includes URLs that have a value (empty cells are skipped)

2. **`[domain]-sitemap-index.xml`** - Sitemap Index
   - References two sitemaps:
     - The HubSpot-generated sitemap (from the domain's live site)
     - The custom sitemap (generated by this script)
   - Used when submitting to search engines

## Setting up

This guide walks through setting up the sitemap system from scratch for a **new** set of websites, using the `Sitemap Generator - TEMPLATE.xlsx` file.

The system has three parts working together: a Google Sheet that manages every page URL across every domain and language, a CSV export of that sheet, and a Python script that turns the CSV into XML sitemap files.

---

### Before you start: this must live in Google Sheets

The template is delivered as an `.xlsx` file so it's easy to preview and hand around, but the two working tabs (`SEO Planner` and `Alternate Links Setup`) rely on Google Sheets-only formula behaviour — `FILTER`, `REGEXEXTRACT`, and Google's automatic range-spilling (a single formula that fills an entire row or column on its own). None of that recalculates correctly in Microsoft Excel; editing the raw `.xlsx` will leave you with blank or broken cells.

**Step 1: Convert the template into a Google Sheet.**

1. Upload `Sitemap Generator - TEMPLATE.xlsx` to Google Drive.
2. Right-click it → **Open with** → **Google Sheets**. This creates a native Google Sheet from the file.
3. Immediately rename the new Sheet to something like `[Your Brand] Sitemaps Generator`, and treat that Sheet — not the original `.xlsx` — as your master going forward.

Everything below assumes you're now working in that Google Sheet.

---

### What's in the template

Open the `Start Here` tab first — it has a condensed version of these instructions inline. The working tabs are:

| Tab | Purpose |
|---|---|
| **SEO Planner** | The sheet you edit day-to-day. One row per page, one column per domain/language combination. This is what gets exported to CSV for the Python script. |
| **Alternate Links Setup** | The master list of every language/region your sites support. Adding a row here is how you register a new locale. |
| **Config** | A static reference list of every language and country code (used to build hreflang-style locale codes). You generally never need to edit this. |

The template ships with a small worked example already filled in: 3 example domains (`example-com`, `example-co-nz`, `example-es`), 5 example pages (Home, About Us, Contact Us, Blog, Site Map), and 6 example language/region rows. Use that example to see the pattern before you start replacing it with your own data.

---

### Step-by-step: setting up your first real sitemap

#### Step 1 — List your domains

Decide which physical websites (domains) you need sitemaps for. Each one gets its own column in `SEO Planner` and its own pair of output XML files. Give each a short identifier using the domain name with dots replaced by hyphens — e.g. `acme-com` for `acme.com`, `acme-co-uk` for `acme.co.uk`.

#### Step 2 — Register your languages/regions in "Alternate Links Setup"

For **every** language/region combination any of your sites will serve — including the primary language of each domain — add a row:

- **Column B (Language):** the language name, selected from the list in the `Config` tab's Language column (e.g. `English`, `French`).
- **Column C (Region):** the country/region name, selected from the list in `Config`'s Country column, or `No region specified` if the language isn't tied to one country.
- **Column D (Code):** leave this — it's a formula that builds the locale code (e.g. `en-AU`) automatically from columns B and C.
- **Column E (Homepage):** the full homepage URL of the domain this row belongs to.

The order you add rows here determines the column order in `SEO Planner`, so it's worth listing your primary domains first, in the order you want them to appear.

**Important:** the Homepage URL in column E is how the system links a language/region back to a physical domain. Two rows with the exact same Homepage URL will be treated as the same site serving two different locales (this is how you add extra hreflang alternates — like a UK or Canada variant — without creating a whole new domain column; see the example rows in the template).

#### Step 3 — Set up "SEO Planner"

**Row 1 — domain identifiers:** starting in column B, type the domain identifiers from Step 1 — one per column — for every domain that should get its own dedicated set of sitemap files. Only fill in Row 1 for "primary" domains; leave it blank for columns that just represent an extra language alternate of a domain you've already listed (matching the pattern in the template's columns E–G).

**Rows 2 and 3 — headers:** these are formulas, already in place in column B, and they automatically spill across every column as you add rows to Alternate Links Setup. You shouldn't need to touch these — just make sure you don't accidentally type over columns C onward in rows 2–3, since that would break the spill.

**Row 4 onward — one row per page.** For each page:

- **Column A:** the page's name/description (for your own reference only — not used by the script).
- **The "hard-coded" columns (B, C, D… matching your primary domains from Row 1):** type the actual URL for that page on that domain. Leave a cell blank if that page doesn't exist on that domain.
- **The "formula" columns (everything after your primary domains):** these need the formula only once, in **row 4** (the Home row) — copy it from the template's column E, F or G and update the column letter references to match (e.g. for a new column H, change every `E3` to `H3`). Once it's in row 4, Google Sheets automatically spills the correct value down for every row below it — do **not** paste it into rows 5, 6, 7, etc., or you'll break the spill.

#### Step 4 — Recalculate and sanity-check

1. In Google Sheets, force a recalculation with **Ctrl+Shift+F9** (or File → nothing needed, but a manual edit anywhere usually triggers it).
2. Scroll across `SEO Planner` and confirm: every column has a sensible header in Row 2 (e.g. "English | Australia"), Row 3 shows a locale code, and your formula columns are pulling the right URLs down every row.
3. Spot-check one formula-based cell against the domain it should be copying from.

#### Step 5 — Export to CSV

1. In Google Sheets, make sure the `SEO Planner` tab is the active tab.
2. **File → Download → Comma-separated values (.csv)**.
3. Rename the downloaded file to `data.csv`.

#### Step 6 — Set up the Python script

1. Copy `sitemap-generator.py` (from the project) into a new working folder.
2. Put `data.csv` in the same folder as `sitemap-generator.py`.

#### Step 7 — Run it

```bash
python sitemap-generator.py
```

This creates a `sitemaps/` folder containing, for each primary domain:

- `[domain]-sitemap.xml` — every page URL for that domain, with `<xhtml:link>` alternates for every language/region that maps back to it.
- `[domain]-sitemap-index.xml` — a small index file referencing both the HubSpot sitemap and the custom one above.

#### Step 8 — Validate and deploy

1. Open a generated `[domain]-sitemap.xml` and check it looks right — real URLs, no stray blank `<url>` entries, hreflang alternates present where expected.
2. Upload both files to the HubSpot file manager, ensuring each is uploaded to its matching domain.
3. Submit the sitemap index URL to Google Search Console for each domain.

---

### Common first-setup mistakes

- **Editing the raw `.xlsx` in Excel instead of converting it to a Google Sheet first.** The formulas will look broken because Excel can't evaluate them — see the note at the top of this guide.
- **Pasting the formula-column formula into every row instead of just Row 4.** Only Row 4 needs it; it spills down on its own. Pasting it into every row usually still works but defeats the point and makes future edits fragile.
- **A language/region's Homepage URL (column E in Alternate Links Setup) doesn't exactly match a Row 4 URL in SEO Planner.** The match is an exact text match — trailing slashes, `http` vs `https`, and `www.` all matter. If they don't match character-for-character, that alternate will silently resolve to blank.
- **Forgetting to re-export the CSV after editing the Sheet.** The Python script only ever reads `data.csv` — it never touches the Google Sheet directly.

## How to Use This System

### Running the Script

1. **Update the Sheets file** - Make changes to the SEO Planner sheet (see instructions below)
2. **Export to CSV** - Save the sheet as `data.csv` in the same folder as `sitemap-generator.py`
   - The formulas will automatically resolve to their calculated values
3. **Run the script:**
   ```bash
   python sitemap-generator.py
   ```
4. **Check the output** - Review the generated files in the `sitemaps/` folder
5. **Upload files** - Deploy the XML files to their respective domains' HubSpot file managers

---

### Adding a New Page to an Existing Domain

**Steps:**

1. Open your master spreadsheet
2. Go to the "SEO Planner" sheet
3. Add a new row with:
   - **Column A:** Page name/description
   - **Columns B-D:** Hard-coded URLs for each of the primary domains
     - Leave cells blank if the page doesn't exist on that domain
4. Save the Sheets file
5. Export the SEO Planner sheet as `data.csv`
6. Run: `python sitemap-generator.py`
7. The new page will appear in all generated sitemaps with all its language variations

**Why it works:** The new row will have formulas automatically applied to columns I+ (if they exist), so all derived domains will automatically get the URLs they need.

**Example:**
If you're adding a "Features" page for example-com (English | US), and it has an equivalent on example-co-uk (English | UK):
- Column A: "Features"
- Column B (example-com): `https://example.com/features`
- Column C (example-co-uk): `https://example.co.uk/features`
- Columns E+ with formulas will automatically calculate their values based on these hard-coded URLs

---

### Adding a New Region/Language to an Existing Domain

This is **handled automatically** by the formula system:

1. Open your master spreadsheet
2. Go to the "Alternate Links Setup" sheet
3. Add a new row with:
   - **Column B:** Language name (e.g., "English")
   - **Column C:** Region name (e.g., "Canada")
   - **Column D:** Homepage URL for this language/region combination (e.g., "https://www.example.com")
4. Save the Sheets file
5. Go back to the "SEO Planner" sheet — a new column will appear automatically with the heading "English | Canada"
6. The formula-based columns (E+) will automatically pull from the matching "example-com" column
7. Export to CSV and run the Python script

**No manual setup needed** — the formulas take care of everything.

---

### Adding a New Domain to the Maps

**This is the most complex change**, requiring updates to multiple places.

#### Part 1: Update the Alternate Links Setup Sheet

1. Open your master spreadsheet
2. Go to the "Alternate Links Setup" sheet
3. Add rows for each language/region combination your new domain will support:
   - **Column B:** Language
   - **Column C:** Region
   - **Column D:** Auto-generated locale code
   - **Column E:** Homepage URL of the domain
4. To keep things tidy, group the first new row with the other unique domains at the top of the sheet.
5. Save the file.

#### Part 2: Update the SEO Planner Sheet

1. Go to the "SEO Planner" sheet
2. In the newly created column, add the top-level domain using hyphens instead of periods (e.g., example-ca) to row 1.
3. Fill in URLs for any pages with equivalents (Rows 4+).
4. Save the file.
5. Export SEO Planner to CSV
6. Run: `python sitemap-generator.py`
7. New sitemap files will be generated in the `sitemaps/` folder

**Important checklist when adding a new domain:**
- [ ] All language/region combinations are defined in Alternate Links Setup
- [ ] Domain identifier in Row 1 of SEO Planner matches the key in SITE_CONFIG
- [ ] The HubSpot sitemap URL is correct (test by visiting it in a browser)
- [ ] The custom sitemap path uses the correct format (usually `/hubfs/[domain]-sitemap.xml`)
- [ ] Run the script and verify output files are created
- [ ] Check one generated XML file to ensure it looks correct

## Troubleshooting

### Script runs but generates empty or incorrect sitemaps

**Check:**
1. Is `data.csv` in the same folder as the script?
2. Are the domain identifiers in Row 1 of the CSV exactly matching the keys in SITE_CONFIG?
3. Are there actual URLs in Rows 4+? (Empty cells are skipped)
4. Did the formulas resolve correctly when you exported to CSV? (Open the CSV in a text editor to verify it contains URLs, not formulas)

### Column headings in SEO Planner show errors or wrong values

**Check:**
1. Are all language/region combinations defined in the Alternate Links Setup sheet?
2. Are the formulas in Row 2 of SEO Planner referencing the correct sheet name?
3. Try recalculating the sheet (Ctrl+Shift+F9 in Sheets) to refresh formulas

### New region added to Alternate Links Setup doesn't appear in SEO Planner

**Check:**
1. Did you save the Alternate Links Setup sheet?
2. Go back to the SEO Planner sheet and scroll right — the new column may be beyond the currently visible area
3. Try closing and reopening the file to force a full recalculation

### Sitemap index references wrong HubSpot URL

**Check:**
1. The HubSpot URL in SITE_CONFIG is correct
2. The URL is accessible (try opening it in a browser)
3. The key in SITE_CONFIG exactly matches the domain identifier in Row 1 of the CSV

### New page doesn't appear in sitemap

**Check:**
1. The URL cell is not empty
2. The page row is after Row 3 (header rows)
3. You exported the Sheets file to CSV (script reads CSV, not Sheets directly)
4. You ran the Python script after updating the CSV
5. If using formula-based columns, verify the formulas resolved to actual URLs in the CSV

### Language alternates not showing in custom sitemap

**Check:**
1. All language/region combinations for that domain are defined in Alternate Links Setup
2. All language/region codes are listed in Row 3 of the SEO Planner
3. URLs exist for each language (cells aren't empty)
4. The CSV export resolved all formulas to actual URL values

## File Naming Convention

The script automatically generates files with this naming pattern:

- **Custom sitemaps:** `[domain-identifier]-sitemap.xml`
  - Example: `example-com-sitemap.xml`, `example-co-uk-sitemap.xml`

- **Sitemap indexes:** `[domain-identifier]-sitemap-index.xml`
  - Example: `example-com-sitemap-index.xml`, `example-co-uk-sitemap-index.xml`

When uploading to HubSpot, upload to the File Manager, outside of any folders.

## Quick Reference: The Formula System Explained

For those who need to understand the formula-based columns (E+):

**The formulas work like this:**

1. They look at the column heading (Row 3) to identify what language/region is needed
2. They use Row 3's language/region code to search the Alternate Links Setup sheet
3. They find the matching row in Alternate Links Setup
4. They use `INDIRECT()` and `ADDRESS()` to return the value from the corresponding hard-coded column (B-D)

**Example:** Column I, row 3 is "en-CA"
- The formula says: "Find the row in the Alternate Links Setup sheet that has 'en-CA' in column D"
- Then retrieve the homepage URL from column E in that same row.
- Use that homepage URL to find the correct column in the SEO Planner page.
- Use that column to populate the new column.
- If no match is found or there's an error, return blank.

This design allows:
- Unlimited derived domains without manually entering each URL
- Changes to hard-coded columns automatically cascade to formula-based columns
- New language/regions to be added in Alternate Links Setup and automatically available

## Next Steps / Maintenance

- Regularly update the SEO Planner sheet as new pages are added to your sites
- When adding multiple new regions, update Alternate Links Setup first, then SEO Planner
- Test generated sitemaps by validating them with Google Search Console
- Monitor language/region code consistency between Alternate Links Setup and SEO Planner
- When updating sitemap files in HubSpot, ensure the old versions are backed up
- Document any domain-specific quirks, redirects, or special cases in comments within the Sheets file
